# Failure Prediction on CartPole Trajectories: Data Preparation and Supervised Baselines

> **Contents.** Sections 1–9 document Workshop 1 (data preparation and supervised baselines). Section 10 documents Workshop 4 (autoencoders and variational autoencoders), which reuses the same dataset, split and features.

## 1. Overview

This folder contains the Workshop 1 project of the Machine Learning course (Semester 2026-III, Universidad Distrital Francisco José de Caldas). It implements a binary classification task on CartPole trajectories: given the state `(x, x_dot, theta, theta_dot)` and the `action` at time `t`, predict whether the episode is about to fail (`label = 1` in the last 5 steps of every failed episode). The project includes dataset verification, exploratory data analysis, a leakage-free preprocessing pipeline (episode-level split), three supervised baselines (Logistic Regression, Random Forest, Gradient Boosting) and reproducible experiments with fixed seeds.

**Group:** 5 | **Authors:** `Miguel Angel Torres Ramirez, Cristian David Romero Gil, Omar Esteban Peña Sanchez`

| Dataset property | Value |
|---|---|
| File | `data/raw/cartpole_dataset.csv` (1.99 MB) |
| Rows / episodes | 35,874 / 400 |
| Columns | `episode, t, x, x_dot, theta, theta_dot, action, label` |
| Class balance | 94.51 % class 0 / 5.49 % class 1 (17.2 : 1) |
| SHA256 | `ec067d5dcc498f2b5c5486d24f290283431ef3a0db0a4952cfde84f07e4f53f8` |

Dataset provenance: generated by rolling out CartPole-v1 (OpenAI Gym 0.26.2) with a mixed policy (noisy expert + random actions); all seeds (Python, NumPy, Gym) are fixed to 42. A state is labelled `1` if the episode physically fails within the next five steps (|theta| beyond 12 degrees or |x| > 2.4). CartPole-v1 is free and pip-installable, with no license restrictions for this use.

## 5. Running Experiments

Run every command from the repository root.

### 5.1 Verifying the Dataset

```bash
python dataset_info.py
```

This will:

* Verify the SHA256 checksum (it must print `OK (matches expected)`)
* Print the shape, column types, missing values and duplicates
* Print class counts, imbalance ratio, feature ranges and episode statistics

---

### 5.2 Creating the Train / Validation / Test Split

```bash
python src/dataset.py
```

This will:

* Split the 400 **episodes** (not rows) into 70 / 15 / 15 %, stratified by episode length
* Save the partition in `data/splits.json` (279 / 61 / 60 episodes, seed 42)

The file is already included. Never re-split randomly: every script loads this file.

---

### 5.3 Training and Evaluating the Baselines

```bash
python src/baselines.py
```

This will:

* Build the 16 engineered features and standardise them (statistics from the training set only)
* Train Logistic Regression, Random Forest and Gradient Boosting
* Select the decision threshold on the validation set (maximum F1)
* Print precision, recall, F1, ROC-AUC, PR-AUC, accuracy and the confusion matrix on the test set
* Store the results in `runs/baseline_results_base.csv` and `.json`

---

### 5.4 Ablation Experiments

```bash
python src/baselines.py --raw-only   # only the 5 raw columns (no feature engineering)
python src/baselines.py --augment    # Gaussian-noise augmentation, training set only
```

Results are stored in `runs/baseline_results_raw.*` and `runs/baseline_results_augmented.*`.

## 7. Reproducibility

All experiments are reproducible due to:

* Fixed random seed: 42 (`random`, `numpy` and every scikit-learn model)
* A saved episode-level split in `data/splits.json`, which stores the SHA256 of the dataset it was created from
* Normalisation statistics and augmentation computed on the training set only (no leakage)
* No information from the future in the features, and the time index `t` is not used

To reproduce results:

1. Set up the environment
2. Run `python dataset_info.py` and check the checksum
3. Run `python src/baselines.py` (and the two ablations)
4. Compare with `runs/baseline_results_*.csv`

Main result on the test set (60 episodes, threshold chosen on validation). Reference environment: Google Colab (scikit-learn 1.6.1, pandas 2.2.3, numpy 2.1.3); other library versions may change the Random Forest numbers slightly:

## 10. Workshop 4 — Autoencoders & Variational Autoencoders

### 10.1 Goal

The question for this workshop is what structure unsupervised models find in the CartPole data, and whether that structure helps the downstream task. Pre-failure states (`label = 1`) are treated as **anomalies**. Autoencoders trained only on safe states score each test state by its reconstruction error. The comparison is against the Workshop 1 baselines and the **frozen Workshop 2 deep LSTM**. Everything uses the same 16 features, scaler (fit on train) and `data/splits.json` as Workshop 1.

| Component | Setting |
|---|---|
| AE | `16 → 64 → 32 → z → 32 → 64 → 16`, ReLU, linear output, MSE, z ∈ {2, 4, 8} |
| VAE | same trunk, heads μ and log σ², reparameterisation trick, loss = SSE + β·KL, β ∈ {0.5, 1, 4}, KL annealing over 10 epochs |
| Denoising AE | AE with Gaussian input noise σ = 0.2 (optional extension) |
| Workshop 2 model (frozen) | 2-layer LSTM (64 units) over 16-step raw windows, loaded from `checkpoints/w2_lstm_best.pt` (not retrained); its final hidden state is the supervised encoder |
| Supervised control | MLP with the same input, trunk and z-wide bottleneck as the AE, weighted BCE (separates the effect of labels from the LSTM's temporal context) |
| Training | Adam, lr 1e-3, batch 64, 50 epochs, seed 42, best validation epoch kept |
| Regimes | `all` rows (reconstruction, latent analysis) and `normal` rows only (anomaly detection) |
| Selection | z\* and β\* = best **validation** anomaly ROC-AUC; thresholds = max F1 on validation |

### 10.2 Running the pipeline


### 10.5 Reproducibility notes

* Seed 42 for Python, NumPy, PyTorch, the data loaders and the noise generators; `torch.use_deterministic_algorithms(True)`.
* Checkpoints store the configuration, the input dimension, the feature names and the scaler statistics, so `autoencoder.load_checkpoint` rebuilds a model without extra code.
* Labels are never used to train the unsupervised models. They are used only for validation-based selection and thresholds, and for the final test evaluation.
